# Aeolus Showcase & Seeded Automation Cleanup Pass (30 commits, `4f0cd52^..HEAD`)

The pass rebuilds command evidence as a fixed four-stage proof model with a durable capability snapshot (migrations 017/018), adds a scoped live command feed to custom UIs, separates the simulator from public-demo restrictions, makes showcase seeding reconciling rather than destructive, and then walks every seeded tab re-deriving proof tiers and removing UI-invented physical state. The truthfulness work is substantially real: the `devices.list()` frozen-snapshot defect was traced and fixed in ten projects, eight command echoes were demoted or re-pointed at genuine instruments, and two repo-wide gate tests were added to hold the line. Phase 7 (layout capture) is absent as stated.

**Watch for:** the Bunker Perimeter pane's source file is mojibake-corrupted and renders literal garbage in three visible strings (confirmed); the Power & Supplies pane labels the medical-kit inspection age as the beans' check date and drops MEDICAL entirely, on the pane rebuilt specifically to demonstrate provenance (confirmed); `floodlightPct` and `overpressure` are left stale in summaries emitted immediately after the commands that proved them, so the overview renders "SEALED · 8 Pa positive" and a 0% beam next to an OBSERVED receipt (confirmed); and the audit gate has three invariants that can pass while the property is violated, one of which has a live instance in Game Master (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The evidence platform holds up under the truthfulness test. `commandProof()` reads `reached` only from a recorded transition and `unavailable` only from a recorded capability snapshot, so a pre-017 record says "not recorded" rather than inventing a `false`. `observationConfigured` is gated on a real condition spec, not on the presence of a confirm bag, so the acknowledged-tier commands report "no physical observation configured" rather than implying the author declined an available measurement. Author text is confined to two sanitised caption fields and cannot reach the lifecycle state, the tier, or the device handler.

The live feed is a projection of durable transitions, not client animation: scope is the automation's own `ruleId`, the WS mapping shares `automationVisibility` with the automation's state broadcast, read-only grants are gated on an allowlist rather than a denylist, and no token crosses into the iframe.

What is left of the frozen-snapshot defect is the same problem one rung further out. Several projects now correctly write the field the command asserted, then publish it in a summary alongside a *measured* sibling field the execution could not refresh. Perimeter emits `lightsOn: true` with `floodlightPct: 0`; Air emits `sealed: true` with ambient `overpressure`. Both feed the Bunker Overview, so it renders a 0% beam beside a receipt reading "output reached 70%", and "SEALED · 8 Pa positive · both doors interlocked". Each self-corrects on the next device publish, but the fix pattern applied nine times elsewhere was not applied here.

Two panes carry provenance defects the pass was meant to remove: the beans card renders `medicalCheckedDaysAgo` as its own check date while MEDICAL disappeared entirely, and the overview shortened `STATION` to `STN` in the same pass that banned unexplained symbols.

Three gate invariants are weaker than they read. The projection-key check degrades to substring matching on un-comment-stripped source for eight of the twenty-five projects, including farm-water and Game Master, so a key named only in prose passes. The post-command snapshot check scans only the enclosing function, and Game Master re-reads the snapshot from the caller after awaiting commands — the gate passes, and the comment above the call asserts a refresh the snapshot semantics cannot deliver. The echo-field ban is a global list of eight names while echo-ness is per-fixture; the test's own justifications name five more echo fields that are not on the list.

`commandLadder()`, `commandVerdict()`, `rungProps()` and `verdictProps()` were deleted from `@aeolus/ui` rather than deprecated. §2.9 asked for non-showcase consumers to be reviewed before changing the semantics; removal breaks any user-authored custom UI importing them, with no shim.

Verification: `tsc --noEmit` clean on backend and frontend; the new gate suites, escape-room session, bunker air propagation, capability snapshot and the full frontend sandbox/ui-kit suite pass (565 tests). Every finding below was read out of source, not inferred from a test.

## Commanded field written, measured sibling left stale

```ts
// perimeter-control.ts — projectFloodlightState() ran BEFORE the command
state.set("floodlightPct", isNaN(brightness) ? 0 : brightness);
...
// setFloodlights(), on success
state.set("lightsOn", on);          // commanded value: correct
// floodlightPct: not written
...
// logic/index.ts, immediately after
publishPerimeterSummary();          // lightsOn:true, floodlightPct:<pre-command>
```

The command is verified against `brightness >= 70`, so at settle time the physical brightness *is* ≥70 — the automation simply does not know it. The pane computes `beamPct = model.floodlightPct ?? (lights ? 100 : 0)`, so `0` wins over the fallback: the beam cone disappears, the footer reads `FLOODLIGHTS 0%`, `lit={beamPct > 40}` leaves the contacts unlit, and the receipt directly below says `OBSERVED — output reached 70% of deterrent brightness`. ## Where the audit gate can pass while the property is violated

**Projection keys.** The strict form compares literal `state.set("key"` writes against the UI's `aeolus.read("key")` calls. Any project containing `state.set(<identifier>` trips a fallback:

```ts
const dynamic = /state\.set\(\s*[A-Za-z_$]/.test(project.logic);
const known = written.has(key)
  || (dynamic && new RegExp(`["']${key}["']`).test(project.logic));
```

Eight projects trip it: `bunker-overview`, `escape-game-master`, `escape-puzzles`, `farm-energy`, `farm-water`, `mine-overview`, `vessel-mission-overview`. Two are the pass's flagship panes. `project.logic` is raw source here — only the snapshot check strips comments — and these files carry long explanatory comments, so a key named in prose satisfies the invariant. The whitelist arrays the fallback exists for (`["contacts", "sector", ...].forEach(copyDefined)`) are literal string arrays and could be resolved directly.

**Post-command snapshot re-reads.** The detector finds functions reaching `devices.list()`, closes over helper calls transitively, then for each `await devices.action(` scans only to the end of the enclosing function. Three blind spots, one live:

- A re-read in the *caller*, after the awaited helper returns, is invisible. `escape-game-master/logic/index.ts` does this twice, and `projectRoomLook()` reaches `devices.list()` through `byTopic`. The gate passes. Because the snapshot is frozen for the whole execution the second call returns identical values to the first, so nothing is misreported — but the comment above it ("Refresh what the room is physically doing before and after acting, so the console reports the controller's observed scene rather than the last thing this automation asked for") asserts a refresh that cannot occur, which is the reasoning error the pass removed from nine other files.
- The body regex only matches `function name(...)`, so an arrow-function helper reaching `devices.list()` would not register as a reader. Latent; no project uses one today.
- Only `await devices.action(` is scanned, so a non-awaited call, or one stored and awaited later, escapes.

**Echo fields.** `ECHO_FIELDS` bans eight names globally, and the docstring is explicit that each is "written by its fixture in the same update that accepts the command". Echo-ness is a property of a fixture, not of a field name. The `EXPECTED` table's own justifications name five more fields as echoes for their devices — `demand`, `rpm` and `airflow` (mine-ventilation), `lightPct` (escape-room-fx), `watts` (farm-energy) — none banned. A future author writing `tier: "observed", condition: { field: "demand", op: "gte", value: 80 }` against the ventilation fan passes both gate tests while proving nothing.

The extraction is also fragile in the direction that hides violations. `conditions` is `/condition:([\s\S]*?)(?:timeoutMs|evidence|\n\s*\})/g` — shorthand property syntax has no `condition:` key and contributes nothing, and a single-quoted `field: 'on'` defeats `not.toContain('field: "on"')`. Because every assertion is file-level, "declares a condition wherever it asks for an observed tier" is satisfied by any one compliant condition anywhere in the file, so a second `observed` command in the same file needs none.

**Execution grouping.** The receipt-count invariant short-circuits:

```ts
if (project.logic.includes("devices.executionEvidence(")) {
  expect(project.logic).toContain('state.set("lastExecution"');
  return;
}
```

Only `stage-show-sequencer` uses this, and it does group correctly — every entry point calls `publishExecutionProof()`. The exemption is unconditional, so a project could issue commands from several entry points, group one, and satisfy the gate with no receipt for the rest.

## Escape room lifecycle

The gap is in `startGame()`:

```ts
await setExit(false);
state.set("remaining", SESSION_SECONDS);
state.set("status", "running");
state.set("timerStartedAt", Date.now());
```

`setExit` writes `exitUnlocked` only on success. If the maglock command fails verification the session still transitions to RUNNING with a full clock while `exitUnlocked` retains whatever the previous session left — `true` after a completed game. The comment immediately above says "The exit is secured by a verified command rather than left to the reset's side effect. A session must not begin on the assumption that the door is shut," which is what the code does not implement. It self-heals on the next `escape/observed/puzzles` event, because `reconcileExitForCompletion(false)` re-issues the secure, but the pane can show RUNNING over an unlocked exit until then.

`sendHint` passes `deviceId: screen.id` with `tier: "acknowledged"` and no condition. `buildConfirmOptions` returns `undefined` without a condition spec, so the option is inert and the capability snapshot is unaffected — a dead argument rather than a defect, worth removing so it does not read as a configured observation.

## Livestock recall

Containment lands on the first frame past `RECALL_DRIVE_END` (0.55 of 6000 ms over 24 steps → ~3.5 s), inside the command's 5 s window, with the dogs trotting home for another 2.5 s after the command settles.

Two residuals. During the drive the strays are reported `outside: true` all the way to the paddock centre, including the frame at `driven === 1`, so for one frame an animal is drawn inside the boundary flagged as outside. And the pane derives the mob from `cattle.slice(0, cattle.length - strays)` while drawing strays from `strayPositions`: if `strays > 0` with an empty `strayPositions` — state written by an older revision, or a collar publish carrying the count without positions — the header says "2 OUTSIDE" and nothing is drawn outside.

## Wildlife hero loop

Widening `wildlife-detection`'s trigger from `sensor/wildlife/#` to `+/wildlife/#` does not create a command loop: `publishNewClassification` dedupes on `detectionState.eventId`, so a deterrent publish re-projects state without re-emitting a classification, and `aeolus/events/+/wildlife/detection/classified` does not match the new pattern. The project issues no `devices.action` at all, so the ownership boundary holds.

Cosmetic: the deterrent sits at x=96 and the animal's closest position is x≈104, so at short range they overlap.

## Power model

Solar was resized from 1800 W to 980 W against an 890 W base load, so at rest the bank trickles upward and will sit at 100% until the low-power scenario is fired, leaving the CHARGING indicator permanently on. Worth confirming on the Pi that this reads as intended rather than as a stuck value.

## Definition of done

Not done, deliberately: the layout workflow. There is no `demo/seed/layouts/showcase-layout.json`, no `demo/operations/capture-showcase-layout.mjs`, and none of the §14.7 tests. §16's Layout bullet is unmet.

Partially done: §16 asks that unsupported evidence stages be "visible as unsupported/not configured, not silently hidden". They sit behind a "View proof" click on every pane — `defaultExpanded` is used nowhere, including on the Water pane §4.4 designates the reference example. The collapsed card carries intent, tier headline and hardware chain, which answers most of §16's questions; the four canonical stage names and the reasons a stage was skipped require the click. A judgement call rather than a defect, but the teaching surface §2.2 was built for is one interaction away everywhere.

Also partial: §2.3's "Requested tier / Available ceiling / Actual proof" triple. The ceiling row renders only when `ceiling !== tier`, and:

```ts
const clamped = requested !== "" && requested !== tier && ceiling !== "" && ceiling === tier;
```

A command asking for `observed` on a device whose ceiling is `acknowledged` but which effectively ran at `dispatch` reports no clamp and no note — the ceiling row appears, the explanation does not.

The rest of §17 checks out: no manufactured stages, no UI lifecycle timers, no second simulator protocol, no token or REST access into the iframe, no SQLite layout source, no DB wipe required for a reseed, no simulator in the base compose, and public-demo restrictions confined to their own overlays.
